How I Hosted My Website On GitHub Pages (for Free!)#

There are a few static site generators where you can use to generate your static websites on GitHub Pages:

  • Jekyll: a simple, blog-aware, static site generator written in Ruby see more.
  • Hugo: a fast, flexible, static site generator written in Go see more.
  • Others

A static site generator is a tool that helps you build a website by turning plain text files (e.g., Markdown) into a complete website with pages, layouts, and links without needing a data base or fancy server setup. Specifically, it’s called “static” because it creates fixed pages (built with HTML, CSS, and JavaScript files) that don’t change each time someone visits (so your site is fast and secure).

There are many open-source templates. Mine was forked from Pascal Michaillat’s Minimalist Hugo template for academic websites. The documentation in the repository is super clear and easy-to-follow.

In addition, to host your personal website on GitHub Pages safely and get a clean URL like https://yourusername.github.io/ instead of yourusername.github.io/hugo-website/:

1. Fork the template#

  • Fork the website template repository on GitHub to your own account.
  • After forking, follow the template’s instructions to edit the content (e.g., update config files, change text, replace images) so it reflects your personal website.

2. Download GitHub Desktop#

  • Install GitHub Desktop.
  • Clone (fetch) your forked repository into a local folder

3. Build your Hugo site#

Open a terminal (on macOS or Linux) and run:

  • cd PATH/TO/YOUR/FORKED/REPO
  • hugo

This generates the static site files into a folder called public.

4. Deploy to GitHub Pages#

  • On GitHub, create a new repository named: yourusername.github.io
  • Upload the contents of the public folder into this repo.

⚠️ Important: upload only the contents (HTML, CSS, JS, etc.), not the public folder itself.

5. Done 🎉#

  • Visit https://yourusername.github.io/ to see your live website.

Lastly, remember: your website will only deploy if the hosting repository is public. Sometimes deployment takes a few minutes, so be patient, and if something goes wrong, check the Actions tab to debug any errors in the workflows.
